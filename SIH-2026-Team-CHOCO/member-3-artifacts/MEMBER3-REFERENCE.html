Why this matters: the artifact/page must apply a color in the unstamped state too. Every token is declared on bare :root first; the media query and the explicit toggle only redefine it. No token lives only inside a dark block, or the Command Center renders light-on-light.

Color-blind safe: risk is shown as color + a label pill ("High") + sometimes a symbol (▲/●/▼) and a density edge. Never rely on hue alone to convey severity.

06 Command Center

The inspector's desk — intelligence, not forms

Dark, dense, realtime. An inspector runs 12+ cases; everything must be findable, not hunted.

VIEW 1 · MAP

Live ATM heatmap

Leaflet + a heatmap overlay. 500+ clustered markers, risk-coded, WebSocket-updated. Red high / amber medium / green low.

VIEW 2 · GRAPH

Money-trail graph

D3 force-directed rendering of Neo4j subgraph: victim→mule→mule→ATM. Click a node → detail panel.

VIEW 3 · LLM

Natural-language agent

Ask "mules linked to C1001" and get text + chart + graph + suggested follow-ups.

VIEW 4 · ACTIONS

Action panel

Trigger Step-Up Verification, Request Freeze, Generate FIR draft, Dispatch patrol — all with confirm modals.

VIEW 5 · ALERTS

Realtime feed

WebSocket-pushed priority alerts with unread badges + toasts for high-risk predictions.

VIEW 6 · CASES

Complaint detail

Timeline, evidence (verifiable against IPFS/blockchain hash), linked mules, status history.

Map spec

  • Tile layer: OpenStreetMap (no key). Heat = Leaflet.heat weighted by risk_score.
  • Markers: circle markers colored by risk; >= 80 → show on top; click opens AtmPopup (id, block, risk, predicted windows, connected mules, "Open case").
  • Controls: zoom, pan, reset view; filters for time range, fraud type, min-risk slider.
  • Realtime: a new prediction.new WS event re-positions/elevates the controlled marker within 2 s.
  • Performance: marker clustering (Leaflet.markercluster) keeps 500+ markers at 60 fps.

Graph spec

  • Feed: GET /api/mules/{complaint_id}/graph → {nodes:[], edges:[]} (shape in §9).
  • Node shape/color encodes type (victim, mule, upi, phone, bank, atm); ring width encodes mule_score.
  • Interactions: zoom, pan, drag nodes; select highlights neighbors (≤100ms); a small legend + minimap.
  • Simulation: D3 forceSimulation + forceLink + forceManyBody; freeze layout on select for stability.

LLM agent spec

llm-agent / interaction contract
# Officer types (natural language):
"Show all high-risk ATMs in Indiranagar linked to investment fraud in the last 2 hours"

# Backend (M1/M2) turns it into a constrained Cypher query:
MATCH (c:Complaint)-[:CONNECTED_TO]->(a:ATM)
WHERE c.type = "Investment" AND a.area = "Indiranagar"
   AND a.risk_score > 70 AND c.created_at > datetime() - "2h"
RETURN a.id, a.area, a.risk_score, COUNT(c) AS complaints

# UI renders: result table + map pins + a "Repeat for: last 6h" quick action.
# Vague query? backend returns {clarification: "...", suggestions:[...]} → I render the prompt.
  • Chat thread persists in localStorage per inspector; "save as template" writes to backend.
  • Structured QueryBuilder (pick entity → attribute → operators) is a full visual alternative to typing — no cypher skill needed.
  • Response budget: < 5 s including the LLM call; show skeleton + streaming text.

Token handling in ui-kit

packages/ui-kit/src/lib/http.ts
// Single axios instance shared by all apps. Interceptors do auth + refresh.
const http = axios.create({ baseURL: "/api", timeout: 10000 })

http.interceptors.request.use(cfg => {
  const t = localStorage.getItem("access")
  if (t) cfg.headers.Authorization = `Bearer ${t}`
  return cfg
})
http.interceptors.response.use(r => r, async err => {
  if (err.response?.status === 401) {
    const ok = await attemptRefresh()      // calls /api/auth/refresh once
    if (ok) return http(err.config)     // replay original request
    emitAuthExpired()                         // → route to /login
  }
  return Promise.reject(err)
})

Security hygiene (in all three apps)

  • Store tokens in localStorage for this demo so refresh works across tabs; note as an accepted trade-off (HttpOnly cookie is the prod upgrade).
  • Every API input validated client-side with the same Zod schema backend uses.
  • Prefer backend-enforced PII masking (backend already masks victim phone/name in payloads).
  • Logout clears tokens + calls /api/auth/logout.

Anticipated judge questions (my answers)

  • "Vague question?" — the agent returns a clarification prompt + suggestions, which the UI renders.
  • "Privacy?" — JWT + role-based access; backend masks PII; evidence hashed and encrypted.
